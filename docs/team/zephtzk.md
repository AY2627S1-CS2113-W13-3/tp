# Zeph Tang Zhenkai - Project Portfolio Page

## Overview

LabLog is a command-line application for laboratory technicians who lend electronics equipment to students. It tracks equipment, borrowers, loans, reservations and faults, and keeps every record in one validated local file.

### Main contribution: v2.1 UI overhaul

I redesigned the CLI so commands and results are easier to read in both consoles ([PR #156](https://github.com/AY2627S1-CS2113-W13-3/tp/pull/156)).

* **Input and navigation:** I replaced JLine because our group had not received approval to use it ([PR #167](https://github.com/AY2627S1-CS2113-W13-3/tp/pull/167)). The replacement uses normal line input. Enter moves to the next page, `b` then Enter goes back, and `q` then Enter closes the result. Help and overview sections start on new pages. Blank lines fill the remaining space so the page height stays consistent.
* **Clearer output:** I grouped help by section and added colour labels for headings, statuses and feedback. Each page shows the result title and current section so users can keep track of what they are reading. I kept presentation at the output boundary so command handlers do not need their own display logic.
* **Terminal layout:** I added word wrapping and made wide tables switch to numbered records with labelled fields. Long identifiers, empty fields and Unicode text are retained. Wrapping keeps joined emoji and combining marks together, with conservative width estimates. The replacement reads the layout size at startup instead of adjusting when the window is resized.
* **Shared behaviour:** I applied the same presentation to both consoles, kept `NO_COLOR` support, and retained plain output for redirected input. Commands and saved data stay compatible. The shared input interface handles guided prompts, results and end-of-input in both consoles. Paging responses stay out of command history, and invalid navigation can be corrected without losing the result. The earlier version used boxed editing and arrow keys; Kwan Tze extended that pager in [PR #159](https://github.com/AY2627S1-CS2113-W13-3/tp/pull/159).

### Other enhancements implemented

* **Borrower registration and loan listing** ([PR #18](https://github.com/AY2627S1-CS2113-W13-3/tp/pull/18)): I added `add-borrower` and `loans`, with validation of the NUS student ID, name, phone number and email. Duplicate IDs and invalid details are rejected before saving. The loan query reads the shared loan records and reports when a registered borrower has no active loans. Borrowers are saved before publication in memory, so a failed save leaves the live collection unchanged.
* **Borrower contact editing** ([PR #95](https://github.com/AY2627S1-CS2113-W13-3/tp/pull/95)): I added `edit-borrower` to update selected contact details. The borrower ID stays the same, keeping existing loans linked. Users can change one or several fields without re-entering everything. The complete updated record is validated and saved before replacing the old one; invalid changes and failed saves leave the original details unchanged.
* **Export and import** ([PR #96](https://github.com/AY2627S1-CS2113-W13-3/tp/pull/96), [PR #97](https://github.com/AY2627S1-CS2113-W13-3/tp/pull/97)): I added `export FILE` and `import FILE --replace`, and brought the main console's records into one data file. Export preserves the complete application state and refuses to overwrite an existing destination. Import requires explicit replacement, validates a separate copy and saves it before switching the shared books. Existing handlers therefore see the imported equipment, borrowers, loans and related records together. Tests cover paths containing spaces, restart and failed replacement.
* **Invalid-import protection** ([PR #98](https://github.com/AY2627S1-CS2113-W13-3/tp/pull/98)): I added checks for duplicate keys, unknown fields, oversized files and invalid UTF-8. These checks stop malformed or unsupported data from being partially accepted. Rejected imports leave the current records and saved file unchanged; regression tests compare saved bytes and confirm unknown fields are not lost through an unwanted rewrite.
* **Command recall** ([PR #99](https://github.com/AY2627S1-CS2113-W13-3/tp/pull/99)): I added `commands` and `recall INDEX` to both consoles. Users can retrieve the last 20 submitted commands for copying or editing. Invalid indices produce a recoverable error, and recall does not execute the command again or add itself to history. History is session-only, so restarting clears it. This avoids accidentally repeating loans, returns or other changes.

* **Lending fixes:** enabled same-day re-lending and collection within the intended borrower's reservation. Added `recover ASSET_ID` while retaining loss history and return evidence. Recovery rejects repeated requests and dates before the loss report, and unresolved severe faults still block lending. Tests cover other borrowers' reservation conflicts, batch atomicity, restart and export/import ([PR #162](https://github.com/AY2627S1-CS2113-W13-3/tp/pull/162)).
* **Email validation:** accepted mixed-case NUS email domains while retaining the existing student-email rules. Added regression tests to accept valid domain variations and continue rejecting invalid addresses ([PR #160](https://github.com/AY2627S1-CS2113-W13-3/tp/pull/160)).
